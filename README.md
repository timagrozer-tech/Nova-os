# DroidVM — виртуальные машины Android на Android

Приложение запускает внутри телефона полноценную виртуальную машину (QEMU) и позволяет
ставить в неё **свои сборки Android**: Android-x86, BlissOS, PrimeOS (x86_64) или собственные
сборки AOSP под ARM64. Root не нужен.

## Возможности

- Несколько ВМ с отдельными настройками; шаблоны для типичных сборок.
- Гость **x86_64** (BIOS/UEFI, загрузка с ISO и установка на виртуальный диск) и
  **ARM64** (UEFI или прямая загрузка ядра + ramdisk + образов system/vendor/userdata).
- Импорт ISO/img/qcow2/ядер с телефона, создание пустых дисков (qcow2/raw).
- Встроенный экран: тап = касание, два пальца = прокрутка, мышь и Bluetooth-клавиатура,
  экранная клавиатура, кнопки «Назад», «Домой», «Недавние», «Питание», громкость, Ctrl+Alt+Del.
- Сеть (user-mode NAT) и проброс ADB: `adb connect 127.0.0.1:5555` из Termux на этом же телефоне.
- Режим «не сохранять изменения дисков» — удобно для проверки сборок.
- Журнал QEMU и вывод последовательной консоли гостя (логи ядра).
- Поле «Дополнительные аргументы QEMU» и просмотр итоговой команды — для тонкой настройки.

## Как собрать APK

QEMU не компилируется с нуля: скрипт `scripts/fetch_qemu.py` берёт готовые, проверенные
сборки QEMU для Android из репозитория [Termux](https://github.com/termux/termux-packages),
подготавливает их и встраивает в APK.

### Вариант 1 — GitHub Actions (проще всего, ничего не нужно ставить)

1. Создайте репозиторий на GitHub и загрузите туда содержимое этой папки.
2. Откройте вкладку **Actions** → **Build APK** → **Run workflow**
   (или просто сделайте push в `main`).
3. Через ~5–8 минут скачайте артефакт **DroidVM-apk** → `DroidVM.apk`.

Если поставить тег `v1.0` — APK автоматически появится в Releases.

### Вариант 2 — на своём компьютере

Нужны Android Studio (или Android SDK + JDK 17) и Python 3.8+.

```bash
python3 scripts/fetch_qemu.py          # скачает QEMU для arm64-v8a (~50–80 МБ)
./gradlew assembleRelease              # Windows: gradlew.bat assembleRelease
# APK: app/build/outputs/apk/release/app-release.apk
```

`--abi x86_64` дополнительно добавит QEMU для x86_64-устройств (Chromebook и т.п.).
Без шага с `fetch_qemu.py` приложение соберётся, но запускать ВМ не сможет
(на главном экране будет «QEMU: ✗»).

APK подписывается ключом `keystore/droidvm.jks` (пароль `droidvm123`), поэтому новые версии
ставятся поверх старых. Для публикации замените ключ на свой.

## Как пользоваться

### Android-x86 / BlissOS / PrimeOS (ISO)

1. «+ Новая ВМ» → шаблон **Android-x86 / BlissOS / PrimeOS**.
2. «ISO-образ» → «Импортировать с телефона…» → выберите ISO.
3. «Диск 1» → «Создать пустой диск…» (8–16 ГБ, qcow2).
4. Сохранить → **▶ Запустить**. В меню загрузчика выберите *Installation* и поставьте систему
   на диск `sda` (ext4, GRUB — да). Для быстрой проверки можно выбрать *Live*.
5. После установки снимите галочку «Загружаться с ISO».

Если в установщике чёрный экран — добавьте в загрузчике к параметрам ядра `nomodeset`
или `vga=788`, либо попробуйте видео «virtio-gpu» (BlissOS 14+ его поддерживает).

### Своя сборка AOSP под ARM64

Шаблон **ARM64: ядро + ramdisk + образы**:

- **Ядро** — `Image` (arm64), **Ramdisk** — `ramdisk.img`/`initrd`.
- **Диски 1–3** — `system.img`, `vendor.img`, `userdata.img` (в гостях это `/dev/block/vda`,
  `vdb`, `vdc` — порядок должен совпадать с fstab вашей сборки).
- Командная строка ядра — по умолчанию консоль на `ttyAMA0`; допишите, что нужно сборке
  (например, `androidboot.hardware=…`).

Сборка должна быть рассчитана на стандартную плату QEMU **virt** с устройствами virtio:
в ядре нужны `virtio_blk`, `virtio_net`, `virtio_gpu` (DRM), `virtio_input` или xHCI+HID.
Обычные образы эмулятора Android Studio (`sdk_phone64_arm64`) сделаны под модифицированный
QEMU от Google (плата *ranchu*, устройства *goldfish*) и в стандартном QEMU, как правило,
не загружаются.

Шаблон **ARM64 UEFI** — для образов диска/ISO со своим загрузчиком (GRUB/systemd-boot).

## Ограничения (честно)

- **Скорость.** На телефоне нет аппаратной виртуализации для сторонних приложений,
  поэтому процессор гостя полностью эмулируется (TCG). ARM64-гость на ARM-телефоне работает
  заметно быстрее, чем x86_64-гость. Первая загрузка Android-x86 может занять 5–15 минут,
  интерфейс будет медленнее реального устройства.
- 3D-ускорения нет — графика программная.
- Одновременно работает одна ВМ.
- Экранная клавиатура передаёт латиницу (US-раскладка); кириллицу вводите через
  клавиатуру внутри гостевой системы.
- Нужен телефон с arm64 (по умолчанию). На устройствах со страницами памяти 16 КБ
  работоспособность зависит от того, как собраны пакеты Termux.
- ВМ много потребляет: дайте ей не больше половины свободной памяти, держите телефон
  на зарядке.

## Устройство проекта

```
app/src/main/java/com/droidvm/app/
  MainActivity      список ВМ, запуск
  EditVmActivity    настройки ВМ, выбор файлов
  ImagesActivity    библиотека образов
  ScreenActivity    экран ВМ, панель кнопок
  VncView           отрисовка кадра, касания, клавиатура
  RfbClient         клиент VNC (RFB 3.8) поверх unix-сокета QEMU
  KeyMap            keysym / скан-коды
  QemuCommand       сборка командной строки QEMU
  QemuEnv           пути, распаковка прошивок, qemu-img
  VmRunner          процесс QEMU, монитор, журнал
  VmService         foreground-сервис, уведомление
scripts/fetch_qemu.py   встраивание QEMU из Termux
.github/workflows/      сборка APK в облаке
```

Интерфейс написан без AndroidX и XML-разметки — только платформенный API, поэтому проект
лёгкий и собирается быстро.

## DroidVM OS — своя прошивка

Готовая прошивка для DroidVM собирается workflow `Build DroidVM OS` (`os/`) и публикуется в Releases
с тегом `droidvm-os-*`. В приложении она ставится кнопкой «Установить DroidVM OS».

- Основа: [LineageOS for QEMU](https://github.com/jqssun/android-lineage-qemu), ARM64 (LineageOS 23.2, Android 16).
- Root: Magisk, вшит в boot-раздел (`os/patch-boot.sh`); `adb shell su` без подтверждения.
- microG вместо сервисов Google: microG Services + Companion, подмена подписи включена патчем
  `ComputerEngine.isDebuggable()` в `libandroid_servers.so` (`os/patch_servers.py`), подключается
  bind-mount'ом при загрузке. Защита: только если библиотека совпадает с системной; после трёх
  неудачных загрузок подряд патч отключается сам (`/data/local/droidvm/no-spoof`).
- Приложения: F-Droid, Aurora Store (Google Play без Google-аккаунта на устройстве).
- Русский язык, Москва, тёмная тема, анимации 0,5×, мастер настройки пропущен, ADB по сети.

Приложения и библиотека лежат в отдельном разделе `droidvm` диска vda; свои APK можно добавить в `os/apps/`.

Настройка microG после первой загрузки: откройте «Настройки microG» → «Самопроверка», выдайте отмеченные
разрешения, включите «Регистрация устройства в Google» и «Cloud Messaging», затем войдите в аккаунт Google.
